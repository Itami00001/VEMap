# §8. ГЕОГРАФИЯ (v1.1)

Два уровня:

1. **region** — без изменений из v1.0 (85 субъектов, `region_id` = ISO 3166-2:RU).
   Регионы НЕ удаляются: они остаются «обёрткой» для карты (GeoJSON-геометрия).
2. **city** — новая сущность, привязана к региону через `region_id`.

Города MVP (стартовый список, до подтверждения владельцем данных):

```text
Москва            → RU-MOW
Санкт-Петербург   → RU-SPE
Симферополь       → RU-CR
Севастополь       → RU-SEV
Ялта              → RU-CR
Керчь             → RU-CR
Евпатория         → RU-CR
Белогорск         → RU-CR
```

Ограничения:

* Единица данных: `city + (year, month)`.
* Не расширять список городов самовольно — финальный список даёт владелец данных.
* Этнический состав по-прежнему не используется (см. v1.0 §8).

# §12. ВРЕМЕННАЯ МОДЕЛЬ (v1.1)

Основная единица времени:

```text
(year, month)
```

Правила:

* `month` — nullable (для годовых/исторических данных без месяца).
* Приложение **не создаёт данные для несуществующих периодов** и **не интерполирует** пропуски.
* Ползунок времени двигается только по реально существующим периодам `(year, month)`.
* Годы без данных не изображаются как наблюдения (как в v1.0, но теперь в разрезе месяцев).

# §13. MOOD INDEX (v1.1)

* Внутренняя шкала в БД — строго **0–100**.
  Исходные коэффициенты 0–1 / 0–10 нормализуются **на входе** при загрузке.
* Источник расчёта меняется: **тональность текстов** (газеты) — основной источник; опросы — вторичный.
* Формула v2.0 **не утверждена** (блокер: список метрик и словарь тональности — владелец данных).
* До утверждения формулы:
  * расчёт Mood Index **заморожен** (step05 — заморожен);
  * прогноз **заморожен** (step12 — заморожен);
  * `docs/mood-index.md` будет переписан после утверждения метрик;
  * фронтенд трактует Mood Index только как «число + цвет», без знания формулы.

```text

├── id

├── id

```

* Пока структура записи не подтверждена — **не пишем модели глубже `regions`**.

# §38. NLP (v1.1)

Статус: **обязательный модуль**, ядро системы.

Baseline MVP:

* словарный подход (тональный словарь; miniLLM — только по подтверждению владельца данных).

Pipeline:

```text
текст статьи
  ↓
предобработка
  ↓
оценка тональности / эмоций (словарь)
  ↓
метрики (частота слов, темы, тональность)
  ↓
агрегация по городу и периоду (year, month)
```

Тяжёлые модели (RuBERT, transformers) — не подключать без реальной необходимости.

Формат AI-анализа (генерация краткого текста, ответственный — Миша):

```json
{ "city": "...", "year": 2024, "month": 5, "summary_text": "...", "key_topics": ["..."] }
```
